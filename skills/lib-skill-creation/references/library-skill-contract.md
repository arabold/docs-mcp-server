# Единый контракт навыка `lib-*`

## Область и маршрутизация

- Один навык использует ровно одну техническую библиотеку.
- Явное имя продукта, навыка или библиотеки задаёт область без уточнения.
- Неявный выбор допускается только при однозначных ключевых словах.
- Проверяется предметный текст пользователя. Путь к `SKILL.md`, загрузка навыка и служебная инструкция прочитать его не считаются явным указанием продукта.
- При любом реальном пересечении продуктов или предметных областей и уверенности ниже 100% задаётся ровно один короткий вопрос; до ответа инструменты не вызываются, продукт не предполагается, разделы и footer не выводятся. Это правило имеет приоритет над поиском.
- Явные ограничения сохраняются. Непокрытые части отмечаются отдельно, другая библиотека не подключается.
- Инструменты `lib-docs` никогда не вызываются для другой библиотеки. Полностью неподдерживаемая область обрабатывается без поиска.
- В навыке перечисляются термины и признаки маршрутизации, но не конкретные пользовательские вопросы и не демонстрационные ответы.

## Поисковый контракт

- Версия разрешается через `find_version` до первого поиска, когда у библиотеки есть версия или пользователь указал релиз. Несовместимая найденная версия не подменяет запрошенную: поиск останавливается до согласия пользователя.
- Найденная версия передаётся во все последующие поиски.
- Все независимые части запроса объединяются в один начальный поиск. Первый и единственный начальный `search_docs` использует `limit=5`.
- После изучения результатов допустимо не более двух уточнений запроса.
- Абсолютный максимум — три `search_docs` на библиотеку на весь пользовательский запрос, а не на каждый пункт. После третьего поиска работа с библиотекой прекращается.
- Допустимые лимиты — только `5` и `10`; `10` применяется лишь при необходимости.
- `fetch_url` открывает только URL найденного результата и не заменяет поиск.
- `list_libraries` вызывается один раз только для диагностики доступности.
- Существенные утверждения без подтверждения не достраиваются из памяти.

## Формат ответа

1. Прямой вывод в 1–3 предложениях без заголовка.
2. Точный заголовок `## По документации`.
3. Последовательные пункты `### 1.`, `### 2.` и далее.
4. Подтверждённые и непокрытые положения находятся в разных пунктах.
5. После текста подтверждённого пункта идёт пустая строка и отдельная строка:
   `[Источник] {Официальная документация или публикация}; {Раздел}; <{публичный URL}>`
6. Литерал `[Источник]` появляется ровно один раз — только в начале строки источника — и не повторяется после `|`. Несколько источников объединяются в той же строке через ` | `. Каждый фрагмент по обе стороны разделителя является полным источником с собственными названием, разделом и подтверждённым публичным URL. Отдельный URL или раздел после `|` запрещён.
7. Публичный URL берётся только из результата библиотеки или заранее подтверждённой официальной области. Внутренний `file://` не показывается. Если публичная ссылка не подтверждена, строка источника заканчивается после публикации и раздела без поясняющей фразы.
8. Не выводятся даты снимков, `Snapshot date`, `undefined`, приватные адреса и сырой MCP.
9. При необходимости добавляется `## Выводы и рекомендации` с нумерованным синтезом только из подтверждённых положений.
10. Если `search_docs` вызывался, последняя строка имеет точный вид `[Использованы библиотеки: TECHNICAL_NAME]`; после неё текста нет. Если поиск не вызывался из-за неподдерживаемой области или несовместимой версии, используется `[Использованы библиотеки: нет]`. Уточняющий вопрос до поиска выводится без footer.
11. При недоступном MCP, неизвестной версии или отсутствии подтверждения структура не сокращается: состояние оформляется пунктом `### 1.` без выдуманного источника, затем идёт footer по фактическому поиску.

## Структура файлов

- `SKILL.md` — маршрутизация, поиск, границы и ответ.
- `agents/openai.yaml` — interface, зависимость `lib-docs`, неявный вызов.
- Дополнительные `references/` и `scripts/` создаются только когда они реально нужны.
- ZIP-копии не создаются и не обновляются без явного требования проекта.

## Приёмка

- Системный `quick_validate.py` проходит.
- `validate_library_skill.py` проходит.
- Статические тесты репозитория проходят.
- Blind live-матрица в свежих контекстах проходит полностью.
- Реальные трассы подтверждают библиотеку, версию, порядок и бюджеты поиска.
- `git diff --check` не находит ошибок.
